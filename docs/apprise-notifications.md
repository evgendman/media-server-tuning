# Apprise API: Telegram и маршрутизация уведомлений

**Статус на 2026-10-21:** Telegram-доставка проверена тестовыми сообщениями. Маршруты для четырёх категорий работают: критические ошибки, предупреждения, информация о выполнении и новые элементы медиатеки.

Документ описывает именно конфигурацию уведомлений. Установка контейнера, доступ в LAN, прокси, обновление и диагностика сервиса документированы отдельно: [Apprise API на MINI-Ubuntu](apprise-api.md).

## 1. Общая схема

Источники событий (адаптеры, импортёры/экспортёры, задания systemd и Seerr) обращаются к одному Apprise API. Сохранённая конфигурация имеет ключ **arr-stack**. Внутри неё каждой Telegram-теме назначен свой тег Apprise.

Для обычных отправителей используется endpoint:

    http://<MINI-LAN-IP>:8000/notify/arr-stack

Каждый запрос должен явно указывать тег в JSON-поле **tag**. Это предотвращает случайную отправку сообщения во все назначения конфигурации.

## 2. Темы и теги

| Категория уведомлений | Тег Apprise | Telegram topic_id | Тип сообщения для API |
|---|---|---:|---|
| Критические ошибки | **critical** | Уже настроенная существующая тема; числовой ID не был записан в подтверждённом выводе настройки | **failure** |
| Предупреждения | **warnings** | **10177** | **warning** |
| Информация о выполнении | **run-info** | **10181** | **info** или **success** |
| Новое в медиатеке | **library** | **10173** | **info** или **success** |

Все темы находятся в одном личном чате с ботом, у которого включён режим тем (Threaded Mode) через BotFather. У всех адресов используется один bot token и один chat ID; различается topic ID.

Числовые идентификаторы тем получены из поля **message_thread_id** сообщений соответствующих тем через официальный Telegram Bot API. Реальная отправка тестовых сообщений в три новые темы подтверждена пользователем. Тег **critical** и существующая тема критических ошибок также уже проверены.

## 3. Конфигурация arr-stack

Конфигурация хранится в Apprise API и на MINI-Ubuntu в его постоянном каталоге **/opt/apprise-api/config**. Редактирование и проверку тегов выполнять через веб-интерфейс Apprise API.

В TEXT-конфигурации Apprise строка имеет формат:

    <tag>=<notification URL>

Для новых тем используются следующие адреса. Перед добавлением замените **<BOT_TOKEN>** и **<CHAT_ID>** локальными значениями. Эти заполнители не нужно вводить буквально.

    warnings=tgram://<BOT_TOKEN>/<CHAT_ID>:10177/
    run-info=tgram://<BOT_TOKEN>/<CHAT_ID>:10181/
    library=tgram://<BOT_TOKEN>/<CHAT_ID>:10173/

Существующую проверенную строку **critical=...** оставить без изменений. Её точный topic ID не фиксируется здесь, поскольку он не присутствует в проверенном выводе настройки; не подставлять предполагаемый ID.

Секреты не хранить в GitHub, командной истории, логах или исходном коде отправителей. Не публиковать bot token. В публичной документации выше также намеренно не записывается значение личного chat ID. Секретный Telegram URL находится только в локальной конфигурации Apprise.

## 4. Отправка уведомления через HTTP API

API принимает **title**, **body**, **type** и **tag** в JSON. Доступ к API на этом этапе не требует логина и пароля; интерфейс и API ограничены привязкой к LAN-интерфейсу. Поэтому endpoint доступен узлам доверенной домашней сети, а не должен публиковаться в Интернет. Подробности: [Apprise API на MINI-Ubuntu](apprise-api.md).

Пример отправки критической ошибки:

~~~bash
curl -fsS -X POST \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "JacRed adapter",
    "body": "Ошибка синхронизации. Подробности — в журнале службы.",
    "type": "failure",
    "tag": "critical"
  }' \
  http://<MINI-LAN-IP>:8000/notify/arr-stack
~~~

Пример предупреждения:

~~~bash
curl -fsS -X POST \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "Импортёр",
    "body": "Задание завершилось с предупреждениями.",
    "type": "warning",
    "tag": "warnings"
  }' \
  http://<MINI-LAN-IP>:8000/notify/arr-stack
~~~

Пример сообщения об итогах задания:

~~~bash
curl -fsS -X POST \
  -H 'Content-Type: application/json' \
  -d '{
    "title": "arr2torr",
    "body": "Импорт завершён.",
    "type": "success",
    "tag": "run-info"
  }' \
  http://<MINI-LAN-IP>:8000/notify/arr-stack
~~~

Замените **<MINI-LAN-IP>** фактическим LAN-адресом MINI-Ubuntu перед запуском. Выбирайте **type** по смыслу сообщения, а **tag** — по целевой теме. Тип влияет на оформление/семантику уведомления; маршрутизация выбирается тегом.

## 5. Рекомендуемая семантика событий

- **critical**: сбой сервиса, ошибка, из-за которой операция не выполнена, недоступность важного компонента или потеря целостности обработки. Обычно **type=failure**.
- **warnings**: восстановимые проблемы, пропущенные элементы, временные ошибки с продолжением работы и сообщения уровня warning. Обычно **type=warning**.
- **run-info**: итог разового запуска импортёра/экспортёра, количество обработанных элементов, успешное завершение, сводка выполнения. Обычно **type=success** или **type=info**.
- **library**: пользовательские уведомления о новом контенте, который появился в медиатеке. Обычно **type=info** или **type=success**.

Не отправлять каждую строку обычного журнала в Telegram. Для повторяющихся ошибок предпочтительны агрегированное сообщение и ссылка/указание на журнал службы.

## 6. Получение topic ID для будущих тем

1. В BotFather включить Threaded Mode для бота. Для самостоятельного создания тем параметр запрета пользователю создавать темы должен быть выключен.
2. Создать тему в личном чате с ботом и отправить в неё уникальное контрольное сообщение.
3. Через Telegram Bot API **getUpdates** найти соответствующее сообщение и прочитать **message_thread_id**.
4. Добавить новый URL в **arr-stack**, присвоить ему уникальный тег и проверить вкладку Review.
5. Отправить тест из вкладки Notification с этим тегом и удостовериться, что он приходит именно в нужную тему.

Для вызовов Telegram API с MINI-Ubuntu используется уже существующий HTTP-прокси. Не записывайте токен в исходник скрипта или в его аргументы командной строки; используйте скрытый интерактивный ввод.

## 7. Проверка и текущее состояние

На 2026-10-21 подтверждено:

- Telegram API доступен из контейнера через настроенный HTTP-прокси.
- Тестовые сообщения для тегов **critical**, **warnings**, **run-info** и **library** успешно доставлены в соответствующие темы.
- Новые теги и адреса работают в существующей конфигурации **arr-stack**.
- Подключение Seerr к теме **library** ещё не подтверждено отдельным тестом. Использовать topic ID **10173** как целевое значение и выполнить тест после настройки Seerr; поддержка тем личного чата зависит от реализации уведомлений установленной версии Seerr.
