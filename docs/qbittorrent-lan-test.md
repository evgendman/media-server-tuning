# qBittorrent-nox: временный локальный BitTorrent-клиент на MINI-Ubuntu

## Назначение

qBittorrent установлен как отдельный вспомогательный клиент для диагностики автоматического обнаружения пиров и обмена данными между BitTorrent-клиентами в домашней LAN. Он не заменяет основной TorrServer и не меняет его конфигурацию.

Документ описывает саму установку и параметры клиента; хэши, magnet-ссылки и другие идентификаторы конкретных торрентов намеренно не приводятся.

## Установка

- **Пакет:** `qbittorrent-nox` — вариант qBittorrent без графического интерфейса рабочего стола, с управлением через Web UI.
- **Версия пакета на момент проверки:** `1:5.2.3.99~202609291747-9128-a1e4649cb~ubuntu26.04.1`.
- **Источник:** PPA `qbittorrent-team/qbittorrent-stable`.
- **Способ размещения:** пакет установлен непосредственно в Ubuntu; это не Docker-контейнер и не виртуальная машина.

## Изоляция и права

Клиент запущен от отдельного системного пользователя:

- **Пользователь и группа:** `qbittorrent-lan-test`.
- **Домашний каталог:** `/var/lib/qbittorrent-lan-test`.
- **Тип учётной записи:** вход в интерактивную оболочку запрещён (`/usr/sbin/nologin`).
- **Конфигурация и пользовательские данные:** хранятся в домашнем каталоге этого пользователя, отдельно от конфигурации основного TorrServer.

Это ограничение прав и разделение данных на уровне пользователя Linux, а **не полноценная песочница**: процесс работает непосредственно на хосте и использует сетевой стек MINI-Ubuntu.

## systemd и автозапуск

Клиент оформлен как отдельный systemd unit:

- **Unit:** `qbittorrent-lan-test.service`.
- **Файл:** `/etc/systemd/system/qbittorrent-lan-test.service`.
- **Состояние при последней проверке:** `active`.
- **Автозапуск при загрузке ОС:** `disabled`; unit не включён в автозагрузку и запускается вручную для тестов.
- **Перезапуск при сбое:** в unit настроен `Restart=on-failure`; это действует, пока сервис запущен, но само по себе не включает автозапуск после перезагрузки.
- **Защитные параметры unit:** отдельный пользователь, `UMask=0027`, `ProtectSystem=full`, `ProtectHome=true`, `NoNewPrivileges=true`.

Основная команда запуска:

```ini
ExecStart=/usr/bin/qbittorrent-nox --webui-port=8080 --torrenting-port=51414 --confirm-legal-notice
```

## Сетевые параметры

| Назначение | Значение |
|---|---|
| Web UI | `http://192.168.0.14:8080` |
| BitTorrent peer port | `51414/TCP` и `51414/UDP` |
| Основной TorrServer | Отдельный сервис на HTTP-порту `8092`; не заменён и не перенастроен этой установкой |
| Torrent-файлы загрузок | `/var/tmp/qbittorrent-lan-test/downloads/` |
| Незавершённые загрузки | `/var/tmp/qbittorrent-lan-test/incomplete/` |

Проверкой сокетов было подтверждено прослушивание peer-порта на LAN-адресе `192.168.0.14` и loopback. На момент проверки Web UI слушал `192.168.0.14:8080`. В выводе `ss` peer-порт также присутствовал на локальных интерфейсах Docker; это отражает сетевую конфигурацию хоста и само по себе не означает, что qBittorrent запущен в контейнере.

Для тестового клиента были включены DHT, Local Peer Discovery (LPD) и Peer Exchange (PEX); UPnP отключён. Эти настройки относятся к qBittorrent и не меняют параметры Transmission на Keenetic или основного TorrServer.

## Хранение и очистка

Загрузки хранятся под `/var/tmp/qbittorrent-lan-test/`, а не в `/tmp`. На MINI-Ubuntu `/tmp` смонтирован как `tmpfs`, поэтому его содержимое может занимать оперативную память; каталог тестовых загрузок выбран отдельно.

Перед удалением тестового клиента следует остановить unit, проверить, нужны ли загруженные данные, и отдельно удалить только тестовые файлы и конфигурацию. Не следует удалять или изменять каталоги и unit основного TorrServer.

## Проверенное состояние

При последней удалённой проверке:

- пакет `qbittorrent-nox` был установлен;
- `qbittorrent-lan-test.service` был активен, но отключён от автозапуска;
- процесс выполнялся от пользователя `qbittorrent-lan-test`;
- TCP-порт Web UI `8080` и peer-порт `51414` слушали локальный адрес MINI-Ubuntu;
- из рабочего ПК Windows успешно проверялась TCP-доступность адресов MINI-Ubuntu на портах `51414` (qBittorrent) и `45475` (BitTorrent-порт основного TorrServer).

Успешная TCP-проверка подтверждает доступность порта, но не гарантирует автоматическое обнаружение раздач или успешный обмен данными между произвольными клиентами.
